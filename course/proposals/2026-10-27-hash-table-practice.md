## 二、建议新增 H01：哈希表——键值映射、冲突与频次统计

建议先使用临时编号 H01，保留现有 008～022 编号和已有链接；最终编号由 Tutor 决定。

### 目标与前置

- 前置：数组、循环、基本函数；若采用动态桶，先检查 `vector` 的实际使用能力。前缀和已接触，可作为后续组合题的连接点，不把其全部延迟任务清零设为开课门槛。
- 核心目标：学生独立完成一张小型哈希表，理解「映射到同一桶」不等于「key 相同」，并用其完成键值计数/查询。
- 应用目标：能把题意中的「查谁、存什么」转成 key/value，再在后续轻微迁移中与前缀和组合。
- 边界：不把密码学抗碰撞、DHT 路由、字符串滚动哈希当成本课前置；不在一课里复刻标准库的扩容、迭代器、泛型、内存管理等完整功能。

### 建议内容与实现口径

1. 先用一个小问题检查 key、value、bucket、哈希值之间的区别，避免从「什么是数组」重新讲起，也不从口头表现直接认定会实现。
2. 以整数键到出现次数为例，比较直接计数数组与哈希表：键域较大或稀疏时，为什么需要额外的映射与冲突处理；键域小且已知时不强行使用哈希表。
3. 手写固定桶数的简化拉链表。表示方式由 Tutor 按现有能力选定，可用桶内顺序存储，不要求先掌握指针链表。最小操作集为插入/更新计数、按完整 key 查找、查询不存在的 key；删除、自动扩容暂缓。
4. 必须实际制造不同 key 同桶，并验证查询时仍逐项比较完整 key。要区分「同 key 再次出现，需要更新 value」与「不同 key 哈希冲突，需要保留两条记录」。
5. 使用 C++03 兼容语法，遵守 `STUDENT_PROFILE.md`。`std::unordered_map` 属于 C++11，不因构建脚本用 C++17 就默认引入；如 Tutor 建议借助它对照，须先取得学生对新语法/库范围的同意。也不能把 `std::map` 当成哈希表实现来讲。
6. 说明性能依赖哈希分布与负载，避免把查找承诺成无条件常数时间；全体 key 同桶时仍须正确，但性能可能退化。此处只建立直觉，不强塞复杂度证明或防攻击工程。

### 练习与过关证据

- **诊断/模板：**学生独立写出简化拉链哈希表及基本测试，不以复制教师完整实现作独立证据。
- **标准应用：**整数频次统计与查询。题面由 Tutor 选择或建立，不虚构外部题号、难度或 AC 状态。
- **轻微迁移：**在基本表操作稳定后，安排「统计和为给定值的连续子数组」等前缀和计数题。该题同时涉及模型迁移；若前缀和前置不稳，先做去重/重复检测变式，并明确前缀和组合题后续如何补齐，不能据此标记组合应用已掌握。
- **必须覆盖：**空表、未出现的 key、重复插入同 key、不同 key 同桶、零与负键、集中碰撞，以及计数/累计值的整型范围。负键分桶不能产生非法下标；查询不存在的 key 的行为须在题面中明确。
- **24 小时重写：**关闭原代码，重写最小操作及一组冲突测试。
- **7 天轻微迁移：**沿用仓库既有评分和提示等级；独立实现、主动测试、订正后重写及迁移达到协议标准才记掌握。课堂讲完、一次 AC 或教师对拍通过都不能单独替代这些证据。
- 由学生先提供测试输入、预期与理由；教师补充的部分分别记录，不把教师补出的预期记作自主证据。
