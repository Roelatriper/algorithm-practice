# Git 完整操作机制：开课提案

> 提案人：Atri（curator）
> 日期：2026-09-24
> 状态：待 Tutor 决议

## 背景

白衣目前每天在课程仓库里用 git 同步（`add` / `commit` / `pull` / `push`），但这几个动作是沿用既有仓库的惯性，**四层模型、分支机制和冲突处理都没有系统学过**。

新需求（2026-09-24 原话）：希望 Codex 教完整的 git 操作机制，**以后和同学协同做题时不用一大堆微信文件传来传去**。

这是工具链能力，不是算法能力，但它是协作的前提。

## 目标

学完能独立跑完这条闭环，并且知道每一步在动哪一层：

```
拉最新 → 开分支 → 改东西 → 自测 → 提交 → 推送 → 合并 → 处理冲突
```

## 建议的教学范围

| 层次 | 内容 |
|---|---|
| 模型 | 工作区 / 暂存区 / 本地仓库 / 远程，四层各自是什么 |
| 日常最小集 | `status` `diff` `log` `add` `commit` `restore` |
| 撤销 | 改错了怎么退——未暂存 / 已暂存 / 已提交，三种情形分开讲 |
| 分支 | `branch` `switch` `merge`，以及到底为什么要开分支 |
| 冲突 | 冲突怎么产生、文件里长什么样、`<<<<<<<` 标记怎么读、怎么解 |
| 远程 | `fetch` 与 `pull` 的区别、`remote` 到底是什么 |
| 忽略 | `.gitignore` 的写法与常见坑（本仓库刚踩过一次：无扩展名的编译产物） |
| 协作 | 两条路线：加协作者直接推 / fork + PR |

**建议先不碰**：`rebase`、`cherry-pick`、`stash`、子模块。第一次学只会把模型搅浑。

## 建议的教学形式

- **不要干讲命令**。命令清单背下来也没用，要讲「这一步在动哪一层」。
- 建议单开一个 **sandbox 仓库**演练，不要拿课程仓库练 merge 冲突——有污染风险，而且会污染教学记录。
- 最有效的一课是**故意制造冲突**：两个分支改同一行，让白衣自己解决，并解释每个 `<<<<<<<` 标记的含义。
- 与同学的真实协作可以等模型建立后再上手；第一课先单人双分支演练。

## 决策点

1. 是否开这一课？放在阶段 0 的工具链序列里（补课性质）、插在阶段 1 中间，还是等蓝桥杯报名前？
2. sandbox 仓库放哪？curator 建议放在课程仓库之外（例如 `E:/AI/保研/git-sandbox`），避免污染课程历史。请确认位置。
3. 是否包含 fork + PR 流程？协同对象若不是本仓库协作者，就必须学；若是直接加协作者，可以先跳过。
4. 是否包含 `rebase`？（curator 建议：第一轮不含。）
5. 是否要求白衣先交一份「我现在的 git 操作理解」作为诊断材料？
