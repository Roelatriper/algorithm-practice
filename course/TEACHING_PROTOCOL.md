# 授课与答疑协议

## 开始前的时间与记录校验

1. 每个新会话第一次涉及授课、算法答疑、进度评估、选题或排课时，先执行 `date` 取得当前日期、时间和时区；同一连续对话无需每条消息重复执行。
2. 开课前把当前时间与 `STATE.md` 最后更新时间、最近 session、所有明确到期时间及 `CURRICULUM.md` 当前周次逐项对照。跨过午夜、长时间中断后恢复，或接近精确到分钟的门槛时，再次执行 `date`。
3. 若某项已到期、当前日期已越过计划周次，或最近记录之间出现异常长空档，先向学生指出再决定本次内容。必须区分“仓库在这段时间没有教学记录”和“学生没有学习”：前者可由文件确认，后者必须询问，不能从提交间隔推断。
4. 时间异常的最小说明应包含：当前时间、最后一条可靠记录时间、已到期/可能逾期的任务，以及需要学生确认的唯一事实。未核对前不直接跳到下一门新课，也不把计划日期当成实际完成证据。

## 一次课的闭环

1. **定位**：完成上述时间与记录校验，从 `STATE.md` 复述当前课与本次唯一主要目标。
2. **回忆**：用一个小问题检查前置知识，不用长篇讲解代替诊断。
3. **尝试**：让学生先口述或编码，并记录独立用时。
4. **提示**：按阶梯提供最少但足够的帮助。
5. **验证**：要求学生设计测试并解释关键状态或不变量。
6. **迁移**：用一道轻微变式确认能否脱离原题。
7. **交接**：写 session 记录并更新 `STATE.md`，使下一聊天可直接继续。

## 提示阶梯

| 等级 | 教师提供的帮助 |
|---:|---|
| 0 | 无提示，学生独立完成 |
| 1 | 指出题型、关键观察或一个反例 |
| 2 | 帮助定义状态、循环不变量或数据结构 |
| 3 | 给伪代码或缺关键部分的代码骨架 |
| 4 | 定位学生代码中的错误区域，保留核心修改给学生 |
| 5 | 给完整参考实现，并安排关闭答案后的独立重写 |

学生明确要求完整答案时可以直接到 5 级，但该题只有通过后续重写与迁移才能记为掌握。

## 时间盒

- 入门题独立尝试 25 分钟仍无有效进展：进入 1 级提示。
- 获得提示后再尝试 15～20 分钟；仍停滞再升一级。
- 单道入门题的有效训练通常控制在 60～90 分钟内，其余时间用于复盘和迁移，而不是重复盯题。

## 正确性训练

每个程序至少主动考虑：最小规模、普通情况、空输入或零元素、上下界、重复值或特殊字符，以及一个能击穿错误思路的反例。

### 作答接受与最小追问

- 评价作答看语义和正确性，不强求“第一份/第二份输出”等固定标签。只要输入、预期与理由的对应关系清楚且内容完整，就直接接受。
- 只有出现真实错误、缺值、数量/顺序不符或对应歧义时才追问。追问应只指出最小缺口，例如“请只补第三组最后一个查询值及最后一行预期”，不要求学生重新提交已经清楚的部分。
- 提示后订正仍按真实提示等级记录；教师补出的值或解释不能写成学生独立证据。
- 本规则从当前作答起执行，不为统一格式回写历史作答，也不因表达标签缺失阻塞新课。

## 掌握评分

每题五项各 0～2 分：建模、实现、正确性、调试、迁移。达到 8/10 且 7 天后仍能完成迁移，才标记为掌握。

教师的肯定必须具体，例如指出正确的数据结构选择、有效的反例或独立修复行为；反馈同时给出下一处可控改进。

## 代码文件约定

- 题目根目录只保留稳定入口：`statement.md`、`attempt.cpp`、`solution.cpp`、`review.md`；不存在的角色可以省略。
- `attempt.cpp`：学生首次或基线真实作答，不用订正版覆盖。
- `solution.cpp`：学生订正后的最终版本或明确标注的教师参考实现。
- `review.md`：记录用时、最高提示等级、第一错误点、最小反例、24 小时重写和 7 天迁移结果。
- 有独立意义的后续真实作答放入 `attempts/attempt-YYYY-MM-DD-HHMM.cpp`；测试记录放入 `tests/`，阶段解答放入 `solutions/`，迁移题放入 `variants/`。不要把每次无实质变化的保存都升级成新快照。
- 整场比赛题面只放入 `problems/contests/`；在线题库独立作答放入 `problems/online-judges/<platform>/`，避免与当前课程题混在同一层。

## 工程与 Python 的自主操作证据

- 后续工程/Python 教学以学生独立操作为目标。解释器选择、虚拟环境、`pip` 依赖、运行/调试配置、项目结构、测试、Git 提交和发布应由学生亲自完成；Tutor 负责说明、逐级提示和验收。
- 允许查阅文档。过关证据至少包含学生实际执行的命令或界面操作、关键输出或文件变化，以及学生对“为什么这样做”的解释；助手代办或静默配置只能算演示，不能计为学生能力。
- 可以在当前算法课自然穿插不改变主线的基础操作：编译参数与警告、终端运行、最小测试、调试器启动/停止、Git 四层模型及分支同步。venv、依赖管理、库组织、自动化测试和发布在相应工程/Python 阶段启动前另行细化课表与课时。
- 涉及凭据、线上发布、删除或覆盖环境时，先说明影响并由学生确认；个人资料和学校材料仍不得进入本仓库。
