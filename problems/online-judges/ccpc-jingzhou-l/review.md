## 赛场稿的有效逻辑（读码确认）

```cpp
// main: x <= b → 0，否则 js(x,b,d)
js(x,b,d):
    if (x/2-d/2 <= b) {
        tmp = b - x/2;
        if (x/2+tmp <= b) return 1;        // x/2 + (b-x/2) = b ≤ b：恒真
        else return js(x/2+d/2,b,d)+1;     // 死代码，永远不会执行
    } else {
        return js(x/2-d/2,b,d) + js(x/2+d/2,b,d);   // 缺 +1
    }
```

即实际行为：`x ≤ b → 0`（入口）；`x/2−d/2 ≤ b → 1`；否则 `js(x/2−d/2)+js(x/2+d/2)`（无 +1）。

## 确认的错误与修正

1. **一刀分支条件过弱**：`x/2−d/2 ≤ b`（小头 ≤ b）≠ 一刀可行。一刀可行的充要条件是 `x ≤ 2b`（大头应对比 `x/2+d/2`，或等价地对半切 `x/2`）。`x ∈ (2b, 2b+d]` 时小头确实 ≤ b，但一刀仍不可行（`6 2 2` 原稿输出 1）。
   - 学生赛场判断：「稿子里用的是减法，我的错是取了更小的」（在「端点该对着一刀的情形比」提示后自行指出）。
2. **双递归缺 `+1`**（本刀成本）：`6 2 1` 原稿 2，正确 3。
3. **（复习观察）`tmp` 逻辑恒真**：`x/2+tmp = b`，`r_tmp` 分支从未激活——「把大根切到 b」的意图写在了死代码里，条件本身没写对。
4. **（复习观察）基准情形未封闭**：`d` 大时 `f_1 = x/2−d/2` 可能 ≤ b 甚至为负，切割窗口需夹逼 `max(0, x/2−d/2)`；main 的 `x≤b` 守卫只覆盖入口。原稿在部分此类数据上因误差抵消碰对（如 x=3,b=1,d=1e9 手推为 2，碰对），不能当作正确性证据。

## 推导出的模型（学生已验证）

```text
x ≤ b        → 0 刀
b < x ≤ 2b   → 1 刀（对半切永远可行）
x > 2b       → 1 + min 合法切点 (js(左) + js(右))
```

关键推导链（学生可复述的环节）：

- 合法切割窗口：切点 `a ∈ [x/2−d/2, x/2+d/2] ∩ [0, x]`（差 ≤ d ⟺ 切点离中点 ≤ d/2）。
- 一刀收工的切点窗口 `[x−b, b] ∩ [x/2−d/2, x/2+d/2]` 非空 ⟺ `x ≤ 2b`；且 `x/2` 恒在该窗口内——对半切是一刀情形下永远可行的切法。
- 鸽笼：`x > 2b` 时任意一刀必有一根 > b，一刀必不够。
- 下界验证（提示后完成）：`6 2 1` 第一刀后两根都落在 `[2.5,3.5]`，都 > b 且两根都不能再一刀达标 ⇒ 至少 3 刀；`6 2 2` 最优首刀切 2+4（窗口 `[2,4] ∩ [0,2] = {2}`，只有一点可行）。
- 学生反例（正确）：`x=3.5, b=2` 取 `a=1.3 ∈ [0,2]` 但 `x−a=2.2 > 2`——顶回「[0,b] 就行」，确认下界来自 `x−a ≤ b ⟺ a ≥ x−b`。
