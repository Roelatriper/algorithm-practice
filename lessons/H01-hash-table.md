# H01：哈希表——键值映射、冲突与频次统计

## 本课定位

阶段 3 基础算法模型。前置是整数、结构体、循环和 `vector` 的基本使用。学生曾自学哈希表，但仓库尚无独立实现证据；本课诊断承接原定的哈希表口头抽查。当前计划的滑动窗口迁移仍保留为待办，不作为 H01 的前置门槛。

## 唯一目标

独立实现一张固定桶数的简化拉链哈希表，明确区分“同 key 更新”与“不同 key 落入同一 bucket”，并用它统计和查询整数频次。

## 开课诊断

有 7 个桶，整数 key `5` 和 `12` 都映射到桶 `5`（桶编号从 0 开始）。已有 `5 -> 2`，现在插入 `12 -> 1`，再把 `5` 更新成 `3`。请先画出桶 5 中保留的记录，并回答：查询 key `12` 时，为什么不能只看 bucket 编号？负 key `-2` 应落到哪个合法桶？

## 教学步骤

1. 从“某个 key 对应一个 value”的查找需求解释映射；区分 key、value、hash/bucket 编号。
2. 对比直接计数数组与哈希表：键域小且连续时数组更简单；键值稀疏、范围大或未知时，直接开到最大 key 可能浪费空间。
3. 用固定桶数和非负整数取余得到 bucket。指出取余只选桶，不会证明 key 相等；存入同桶的记录还要逐条比较完整 key。
4. 将每个 bucket 表示为 `vector<Entry>`：同 key 则更新 count，不同 key 则在该桶追加记录。这是桶内顺序存储的拉链，不使用指针。
5. 由学生推导负数余数的修正：先算 `key % B`，若结果小于 0 就加 `B`。本课 `B=7`，并检查 `INT_MIN` 不可用 `-key` 取绝对值。
6. 学生先独立完成 `H01` 基础操作题，再完成频次应用 `H02`；学生先给自主测试的输入、预期和理由。
7. 讲解哈希性能的条件：分布较均匀时，桶内记录通常较少；所有 key 都落入同一桶时仍正确，但操作会退化为线性扫描。本课不把平均常数时间当作无条件保证。

## C++ 语法

全程 C++03 兼容。首次出现 `vector<vector<Entry> >` 时解释：外层 `vector` 有固定数量的桶，每个桶内的 `vector<Entry>` 保存落在这里的记录；C++03 的嵌套模板右尖括号之间要留空格。`Entry` 是只含整数 `key` 和 `count` 的结构体。使用 `vector` 的下标、`push_back` 和引用参数，不使用 C++11 的 `unordered_map`、`auto` 或范围 `for`。

## 测试要求

由学生提供完整输入、完整预期和每组用途，至少覆盖空表查询、重复 key 更新、不同 key 同桶、零 key、负 key、不存在 key、集中碰撞和较大频次。测试中必须出现真实碰撞；不能只测不同桶。

## 过关标准

- 能口述 key、value、hash/bucket 的区别，并解释同桶不等于同 key。
- 独立实现 `addOne(key)` 和 `getCount(key)`，查询不存在的 key 返回 0。
- 负 key 映射到合法下标；碰撞时保留不同 key 的记录，重复 key 只更新对应记录。
